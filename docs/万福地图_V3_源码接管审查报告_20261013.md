## 1. 业务定位与角色

**业务目标：**机车俱乐部跑山行程规划、俱乐部活动分享、报名、签到和模拟路线回放。

- **组织者（当前为持有本机浏览器编辑令牌的用户）：**编辑多日行程；设置每日集合点及集合、出发时间；添加景点、管理路线；发布或更新分享；设置活动名额/截止时间/签到半径；查看和导出报名表；移除报名及手工签到。
- **车友（分享链接访问者）：**只读行程、天气、导航、路线模拟；使用大陆 11 位手机号报名，保留本机会员令牌；取消报名或在集合点 GPS 签到。
- **不存在完整的正式会员账号体系：**无需注册登录，组织者权限靠本机 localStorage 中的 token；丢失浏览器数据将丢失该链接的编辑权。不存在云端草稿的自动双向同步。

## 4. 关键数据模型与持久化

### 核心对象

- `Trip { id, title, clubName, days[] }`
- `Day { id, title, date?, avoidHighway?, meetup?, spots[] }`
- `Meetup { name, lng, lat, address?, photo?, meetTime, departTime, note? }`
- `Spot { id, name, lng, lat, tag, note?, stayMin?, address?, photo? }`
- `PackedLeg { p:[lng,lat…], km, min, s?:[endIdx, meters, seconds…] }`：压缩后的路径数据和每个高德 step 的距离/耗时。回放读取该时间分段。
- `SharePayload`：版本号、行程、路线缓存、发布时间。

### D1

- `trips`：分享 ID、分享内容 JSON、SHA-256 编辑令牌摘要、更新时间。
- `trip_reg`：按整趟活动存报名开放、人数上限、截止时间、300/500/1000m 半径。
- `signups`：车友昵称、**明文手机号**、车型、是否带人、备注、报名时间、一次签到数据、会员令牌 SHA-256 摘要；唯一键 `(trip_id, phone)`。
- `writes`：按 IP 写请求时间记录，用于部分 API 频率限制。
- 当前没有外键关联或自动过期/保留策略；没有一人多日签到的独立明细表。

### 数据流

1. 打开 `/` → 从 `ride-planner:v1` 读取本地行程；无数据则给出郑州 2 天示例。
2. 编辑集合点、景点、日期、道路策略 → Zustand 实时更新浏览器本地存储。
3. 地图调用高德获取每段道路、天气；线路存缓存，必要时后续重试。
4. 点击“发布分享” → 发起路由准备 → `POST /api/trips` 创建云端快照并返回 ID 与编辑 token；后续以 PUT 更新。同一浏览器记住 token。
5. 车友打开 `/t/<id>` → Worker 从 D1 注入路线快照；前端设为只读，车友仍可查看、导航、报名/签到。
6. 报名 → `signups` 入表 → 会员 token 仅在返回时传给该浏览器；后续通过 `X-Member` 操作本人记录。
7. 组织者凭 `Authorization: Bearer <edit token>` 操作报名设置、名单、移除和手工签到。
8. 定位签到：浏览器提供 WGS84 坐标，Worker 转换为 GCJ02 并与选定日集合点计算距离；距离在设置半径加最多 100m 精度宽容范围内允许签到。
9. 回放只是对已规划路线做模拟加速播放，**不是真实摩托 GPS 实时追踪**。

## 5. API 清单

| 方法 | 路径 | 权限及作用 |
|---|---|---|
| GET / HEAD | `/`、`/t/:id` | 返回内联 HTML；分享页从数据库注入已发布路线 |
| GET | `/healthz` | 返回 ok/是否配置高德凭据/是否绑定数据库（不是数据库查询探活） |
| POST | `/api/trips` | 公开创建行程，返回编辑 token；按 IP 限流 |
| GET | `/api/trips/:id` | 公开读取发布的路线 JSON |
| PUT | `/api/trips/:id` | 必须提交组织者 token；更新整份路线 JSON |
| GET | `/api/trips/:id/reg?day=…` | 公开计数、昵称和到场状态；本人凭会员 token 读取自身状态；组织者凭编辑 token 读取全部名单/手机号 |
| PUT | `/api/trips/:id/reg` | 组织者更新开放/名额/截止/签到范围 |
| POST | `/api/trips/:id/signups` | 匿名报名，手机号去重、名额限制 |
| DELETE | `/api/trips/:id/signups/me` | 会员用本机 token 取消自己的报名 |
| POST | `/api/trips/:id/checkin` | 会员凭 token 上传定位坐标签到 |
| DELETE | `/api/trips/:id/signups/:sid` | 组织者移除某报名 |
| POST | `/api/trips/:id/signups/:sid/checkin` | 组织者代签到 / 撤销 |

## 6. 重点问题（按优先级）

### P0：正式运行前应先处理

**P0-1 测试/截图脚本直接写线上数据，缺少可靠隔离。**
- `scripts/e2e.py:16` 默认目标为已部署的 `workers.dev` 主站；测试会创建真实分享与报名。
- `scripts/e2e.py:366-392` 清理脚本调用原运行沙箱的绝对路径；没有强制检查 `subprocess.run(...).returncode` 就打印 `TEST_TRIP_DELETED`，因此“显示已清理”不能证明数据库已清除；提前异常也可能绕过末尾清理。
- `scripts/shot.py:1-15, 66-77` 重发布示例分享并替换其编辑 token 哈希；还向线上插入/删除示例名单。**不能当成只读截图工具执行。**
- 处理：创建独立测试 Worker + 独立 D1 + 独立高德测试凭据；全部回归测试默认本地/测试环境；对线上目标 fail-closed；显式要求确认且以真实 DB 核查清理结果。

**P0-2 缺少活动数据生命周期与用户信息保护方案。**
- `schema.sql` 存储明文手机号、签到时 GPS 坐标和报名备注，未见保留期限、自动删除、完整删除行程 API、备份恢复规范和同意机制。
- 处理：增加隐私告知和收集必要性确认；限制后台读取、日志泄露和导出权限；数据到期自动清理；按活动可删除个人信息与签到记录，必要时加密敏感字段；明确数据备份恢复。

### P1：影响正确性、可维护性或规模

**P1-1 多日签到互相覆盖。**
- `worker.js:285-286,303-304` 在 `signups` 同一行覆盖 `checkin_at/checkin_day`。第一天签到在第二天签到后不再计入第一天到场人数；多日活动统计和导出有误。
- 处理：独立 `checkins` 表，唯一键 `(signup_id, day_id)`，保留每个自然日/行程日的签到记录、方式、时间。

**P1-2 签到日和时间窗后端校验不严。**
- `worker.js:274` 未找到提交的 `day` 时退回首日；`worker.js:263-287` 未按已发布的活动日期或签到时间窗口限制提交；可信成员在活动开始之前/结束后也可请求签到。
- 处理：必须校验 `day` 属于行程、该日有集合点且在组织者定义时间窗内；防重复/防滥用；保留手工覆盖审批机制。客户端 GPS 坐标可伪造，定位仅是低信任证明。

**P1-3 路线“发布完成”不等于每一段均为真实道路。**
- `src/share.ts:52` 最多等待 15 秒；`src/routes.ts:232-252` 对已在 inflight 的路由不加入等待队列；失败或超时情况下 `buildPayload` 可遗漏部分路段。分享端可能重新计算或显示直线占位，而不是完整的预加载道路路线。
- 处理：发布前验证每个应有 leg 已 `ok`，否则明确告知“某段尚未规划”并阻止发布/允许标明降级；异步队列应有可正确 await 的任务状态和结果。

**P1-4 道路类型和实际机车合法通行存在差异。**
- `src/routes.ts:134-200, 273-294` 使用的是高德 `AMap.Driving` 和 `mode=car`，只是驾车路线；没有校验本地摩托车禁行道路、景区通行限制或交管规定。反向路线翻转作为容错可能忽略单行线方向要求；挪动终点后补直线也可能不可骑行。
- 处理：导航前明确“驾车参考路线，不保证摩托车合法通行”；审核危险路段和禁摩路段；对反向结果和直线补点标识“需人工核实”。

**P1-5 账号身份仅存浏览器，分享编辑权无法找回。**
- `src/share.ts:16-21, 63-72` 只依靠 `localStorage['wanfu:share-owner:v1']`。同一浏览器只能持有一个当前发布记录；新创建另一活动时会覆盖当前链接的本地访问入口。清缓存、换机后组织者无法恢复。
- 处理：首选俱乐部组织者登录与多活动工作台；短期至少提供安全备份/导入编辑令牌和本机多个发布行程管理，不应公开 token。

**P1-6 CSV 表格公式注入风险。**
- `src/reg.ts:163-169` 按 CSV 语法转义引号和逗号，但用户可提交以 `=`, `+`, `-`, `@` 等开头的昵称、车型、备注；在 Excel/表格软件中可能被当作公式处理。
- 处理：导出时对不可信字段做公式前缀保护；测试 Excel、WPS、LibreOffice 行为。

**P1-7 关键写入安全治理不完整。**
- `worker.js:99-108` 写入限流是先查 COUNT 再 INSERT，非单条原子配额控制；且主要保护发布和新增报名，签到、取消报名、修改设置等请求未按同一层级限流。
- 处理：Cloudflare WAF/Turnstile/速率限制规则 + 后端针对不同端点的访问配额、幂等与行为审计；IP 和 NAT 群体共用限制需仔细设计。

### P2：体验与维护

**P2-1 缺少自定义域名和大陆访问实测。** 交接文档报告 `workers.dev` 在大陆白屏/不稳定；绑定域名并不能单独保证大陆可达，需按实际 DNS/TLS/跨境网络与高德资源加载分别检测。

**P2-2 天气超预报日期会退回实时天气。** `src/weather.ts:105-139` 标记了 `outOfRange`，界面虽有提示，但用户可能将当天实时情况误判为未来出行日的天气。

**P2-3 手机回放 HUD 大，占据地图视野。** `AGENTS.md` 自认约 210px；需通过真实机型和横竖屏布局验证。

**P2-4 公开只读调试钩子。** `src/store.ts:227` 挂载 `window.__wfUI`，`MapView.tsx:17` 挂载 `window.__wfStats`。不是直接的数据库编辑权限漏洞，但生产环境应按构建配置去除或只读限制。

**P2-5 缺乏排序/跨日移动、费用 AA、加油/补给点独立图层、实时共享和 SOS。** 当前只实现规划+活动参与+模拟播放，不要宣传这些尚未交付。

**P2-6 依赖安装、构建、截图脚本环境耦合。** `scripts/e2e.py`、`flicker.py`、`shot.py` 包含 `/workspace/work/wanfu-map`、`/workspace/work/vgrab-cf`、`/usr/bin/chromium` 等原环境绝对路径；异机运行须重构路径配置。

1. 在隔离项目目录使用锁文件恢复依赖、跑 `npm run typecheck`、`npm run build`。
2. 建立 `wanfu-map-staging` 和独立 D1；e2e 默认只指向 staging/localhost，生产地址命中时直接退出。
3. 先修测试清理和脚本硬编码路径，再做桌面 Chrome、Android Chrome、iPhone Safari、微信内置浏览器验证。
4. 建立逐项测试报告：通过/失败、浏览器、时间、截图、控制台、数据库变更核对。

**阶段 C｜功能完整性与安全**
1. 修多日签到、日校验和时间窗。
2. 补删除分享/注销活动、编辑权恢复、手机号及 GPS 信息的生命周期治理。
3. 加强发布路线“全段已就绪”校验，落地 CSV 防公式注入和报名风控。
4. 将驾车路线明确标注为参考路线，排查禁摩/单向线风险。

**阶段 D｜网络和体验**
1. 自定义域名/DNS/TLS/大陆网络访问及 CDN 路径逐层排障，不保证域名一绑即好。
2. 优化手机 HUD、列表排序/跨日移动、活动详情的移动端信息密度。
3. 之后再评估会员账户、俱乐部多活动管理、补给服务、费用分摊、位置共享及 SOS 的独立版本。

## 9. 本轮接管结论

- **可以继续二次开发的 V3 源码：**业务对象清晰、前后端链路成形、组件职责分离、已有部分性能优化和端到端测试框架；不需要从零重写。
- **但还不能认定“已经完成上线验收”：**本轮无法安装完整前端依赖并执行 TypeScript 构建，亦未运行网络、数据库、真机端到端检查。截图、README 与 AGENTS 属于作者交付说明，不能替代实际验证。
- **最危险的接管错误：**把自带测试/截图脚本不经审查直接运行到原线上服务；误认云端已保存本地编辑草稿；误认 GPS 位置可信；把 `AMap.Driving` 误称为经过摩托禁行法规验证的安全路线。
- **后续建议：**冻结 V3 归档基线、优先建立独立测试与备份，再增量修改。避免无授权生产写入和大规模重构。
